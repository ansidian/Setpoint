# Financial Events Map

Durable autonomous accounting for new email arrivals. Documents supply authenticated source facts; related documents describe one financial event. Inbox presentation never owns this queue. Migration 062 establishes the new-arrivals cutoff without enrolling historical mail.

## Files

- `financial-event-service.ts` — public bounded worker; independently assesses complete documents, associates available evidence, immediately plans against Actual, admits an immutable operation, and recovers uncertain writes without dispatching again
- `financial-event-intake.ts` — public durable Gmail forward capture; fixed post-cutoff windows, strict page completion, outage/restart recovery and capture completeness for sources requiring correlation
- `financial-event-store.ts` — atomic revision/claim persistence, permanent provider-reference and schedule-cycle aliases, source-to-event association, operation admission, retry deadlines and status reads
- `financial-event-ai.ts` — exact-request response journal and atomic per-request retry reservations, plus a separate source-keyed document assessment budget
- `financial-event-source.ts` — bounded original-source acquisition reservations and durable complete email/PDF snapshots; underlying source or parser-policy changes invalidate saved evidence
- `financial-event-service.test-utils.ts` — fictional receipt and sender-authentication fixtures for worker behavior tests
- `financial-event-date.ts` — source-bound original-email date policy for authenticated, grounded initial purchase confirmations; revalidates timestamp, semantic context and date provenance before write admission
- `financial-event-evidence.ts` — source hashes and grounded reference keys, conservative complementary receipt matching, compatible fact bundles and conflict detection
- `financial-event-operation.ts` — maps a plan to existing SDK facades, binds the previewed budget and schedule fingerprint, and projects verified operation outcomes
- `financial-event-status.ts` — public read-only ownership and live status facade with latest correction progress and verified outcome/type projection; managed-email reads never trigger the historical planner or another write path
- `financial-event-review.ts` — managed attention projection shared by financial activity and owner-scoped notification changes; groups related receipts and keeps automatic retries silent without reading source bodies
- `financial-event-completion.ts` — public owner-confirmation use case; validates current managed-source revisions, queues confirmed entries or dismisses unsubmitted candidates without writing to Actual
- `financial-event-completion-model.ts` — confirmed-entry validation, immediate manual-review eligibility, immutable source snapshots, compatible later-evidence checks and exact operation construction

## Contracts

- All new indexed arrivals after the migration cutoff are assessed independently of read/dismiss/snooze and Inbox triage admission. Gmail forward acquisition also captures received mail outside Inbox; iCloud retains its configured Inbox scope.
- Classification uses the configured strong email model and honors paused/disabled email AI. Thrown assessment errors share a persisted three-assessment budget per document/source hash; paused checks do not consume it. Assessed candidates with missing dates, failed verification or contradictory purpose remain available immediately; unchanged missing facts never trigger a reassessment timer. Unchanged successful content reuses its assessment; source/authentication revisions invalidate stale work. A negative assessment is explicit and durable. Planning retains complete authenticated bodies, rejecting combined evidence beyond the existing decision limit visibly.
- Authenticated, complementary receipt roles can join only with exact merchant/amount/currency/date, a five-minute arrival interval and unique matches in both directions. Same amount/date alone cannot establish identity. Permanent reference aliases survive bounded correlation history and source changes.
- Reminder/status notices are ignored before missing-fact retries. Utility bill profiles target existing schedules; credit-card statements and card-payment confirmations update schedules using the saved funding/card accounts. Statements require the full statement balance and an explicitly supported due date; missing facts remain reviewable. Unmapped expenses and income remain review-only.
- An authenticated mapped schedule date identifies the cycle by budget and schedule destination; profile recreation or alternative sender profiles cannot forget a handled cycle. Verified unchanged repeats retain their settled receipt even after a later cycle updates Actual.
- Missing authentication and unavailable providers/Actual metadata retry automatically. Missing or conflicting financial facts settle into review with no timer; source or profile revisions may trigger new planning. Ambiguous standalone candidates retain their evidence with no retry deadline and can be completed or dismissed manually. Exact provider/model/purpose/prompt/content requests reuse completed results before adapter dispatch, including incomplete semantic responses, and reserve at most three attempts across crashes and restarts. Fresh source/model/target options get new request identities. Metadata retries never consume the provider budget. Late provider responses remain reusable by immutable reservation token without authorizing Actual writes. A missing automation profile does not prevent a read-only Actual duplicate preview when all source facts and target checks pass; an existing exact result settles without write admission. Conflicting current Actual identity requires attention. Before first dispatch, the exact budget-bound payload and attempt are stored atomically. Every later claim is recovery-only, including after new evidence or a crash.
- Explicit operation dates take precedence. Only an authenticated initial purchase confirmation with strong grounded timing/type/event evidence can use its canonical original email timestamp in America/Los_Angeles. The derived date retains UID, timestamp, timezone and quote alongside the candidate; evidence merging carries date and provenance together. Missing/ambiguous dates in other documents stay unresolved. Owner dates and already-admitted attempts retain their existing authority.
- Production access goes through `server/actual/actual.ts`. Tests write only to disposable databases/budgets. New managed messages cannot also enter legacy parser or generic preflight paths.
- Status exposes pending, waiting, settled and needs-review states plus related-email count and retry time. The legacy import tables and historical observe modes remain unchanged.
- Notification changes group waiting/review events and known financial documents awaiting association. Reads never wake workers; attention keys use the source, required action and latest owner confirmation, so reopening after a new confirmation can alert once while repeated checks stay quiet. Transient retries and unknown assessment failures do not notify. Dashboard and Finance lists use the shared financial-activity reader.
- Owner completion supplies missing facts explicitly and can run while email AI is paused. It preserves original source evidence, invalidates stale automation claims while retaining current linked-source checks and immutable Actual admission/recovery. Fresh revisions permit corrections only before admission while waiting or needing review; an attempted entry cannot be resubmitted. Later related receipts use a separate owner-confirmed identity projection and must have compatible account evidence. Source changes remain visible across restarts and authentication refreshes.

Tests follow the stable-owner policy in `AGENTS.md`; full worker replays keep the store, evidence, planner and operation adapter together while replacing external AI/Actual boundaries.

Every assessed event is eligible for planning immediately. No receipt countdown, account-wide capture cursor, or unrelated document blocks planning or admission. Migration 071's legacy collection columns remain readable for compatibility; collection_required now only distinguishes candidates that expose manual review before a plan is ready from complete profile-backed sources proceeding autonomously. It imposes no wait. Linked source revisions and the current profile/budget still gate admission. The runtime prioritizes ready events between background work; uncertain Actual writes recover from two seconds with backoff capped at five minutes, never redispatching the admitted operation.

Assessed, unsubmitted review candidates expose known facts immediately through shared activity, managed status and notification changes, including during planning. Standalone assessed candidates remain actionable during provider/authentication retries. High-confidence profile-backed events and submitted/attempted entries retain processing presentation. Read projections never change worker state or admit writes; source revisions and the existing completion/dismissal facades remain authoritative. Reassessed unsubmitted sources invalidate prior plans before replanning; unprocessed linked revisions cannot expose an old draft as current. The review form receives the canonical USD amount, never a minimum due or failed amount audit; original extraction remains stored unchanged.

Migration 068 retains owner dismissal timestamps on events and documents. Dismissal preserves identity aliases, suppresses reads/claims/wakes/admission across source changes, clears concurrent leases, and refuses owner-submitted or attempted entries. Standalone candidates receive an event identity on dismissal so matching later receipts remain suppressed.

Migration 069 stores exact financial profiles with a monotonic Settings revision. Profile changes wake unattempted waiting/review plans; null-plan provider backoff remains intact. Automatic admission checks the saved revision and budget atomically. Owner confirmations and attempted immutable operations retain their original authority.

Migration 070 retains complete original-source snapshots and PDF provenance separately from the regularly refreshed email index. Acquisition allows three attempts per underlying source/parser-policy version, including across worker restarts. Source key v2 invalidates snapshots that combined MIME alternatives; subsequent acquisition selects readable HTML with plain-text fallback. A version change alone does not requeue settled documents or alter owner-confirmed/attempted operations. Bill, income, credit-card statement, scheduled-payment and missing-authentication candidates acquire their original message before financial admission.
